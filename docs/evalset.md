# 真实多语种文档评测集（SynthDoG-Doc RealEval v1）

> 分支 `feat/real-evalset`（单独 MR）。门户页面：<https://mmdata-wb.iap.platform.shaipower.com/docintel/synthdog-doc/evalset.html>

## 1. 这是什么、为什么要做

合成数据好不好，最终要看在**真实文档**上有没有用。公开的文档解析评测集（OmniDocBench 等）以中英文为主，小语种几乎是空白，
所以这里从互联网上真实存在的 PDF 里，为 22 个语种 × 9 类版面各找最多 5 份文档、每份抽 2 页，做成与 OmniDocBench
**同一格式**的评测集：官方评分器不用改就能跑，也能和合成集的结果直接比排名。

| 规模 | 数值 |
|---|---|
| 评测页 | 1591 |
| 真实 PDF | 799 份（每格最多 5 份、每份最多 2 页、同一网站最多 2 份） |
| 语种 × 版面 | 22 × 9 = 198 格，其中 192 格有数据、120 格凑满 5 份文档 |
| 原生 PDF（有文字层） | 1399 页（88%） |

凑不齐的格（多为中小语种的报纸、杂志、PPT）**不用合成页或别的语种补**，如实留空，覆盖矩阵见门户。

## 2. 怎么做的

```
FinePDFs 候选（每语种约 4000 份）
  → GPT-6.1-Sol 只看首页文字粗分版面（PPT / 试卷 / 论文 / 报纸 / 杂志 / 书籍 / 教材 / 研报 / 其他）
  → 每格挑 15~40 份取原件：数采平台按原始网址下载（CommonCrawl 对公司出口限流，约四成网址仍有效）
  → 4 页缩略图交 VLM 复核：版面类型、栏数（区分单栏 / 双栏论文）、语种、是否清晰
  → 每格最多 5 份、每份随机 2 页（书籍 / 教材 / 研报 / 杂志跳过封面），PyMuPDF 渲染（长边约 2000 像素）
  → 区域：PP-DocLayoutV3 检测框 + PDF 文字层（检测漏掉的文字层块补成额外区域）
  → 三位标注者独立作答（set-of-mark：在带编号框的图上改类别、删误检、确认或转写文字、写公式 LaTeX 与表格 HTML、
    排阅读顺序、报告没有框住的文字）
  → 共识 → OmniDocBench 格式真值
```

三位标注者：Gemini 4 Argon（effort high）、GPT-6-Astra（max）、Claude Opus 5.5（max；思考耗尽输出额度时降到 xhigh，
如实记录在原始答案里）。按用户决定，本版**不做人工逐页核验**。

### 共识规则

| 字段 | 规则 |
|---|---|
| 区域类别 | 多数票；三人各不相同时取 Gemini（不在被测名单）的判断，再不行取检测器类别 |
| 文本 | 文字层 + 至少 2 人确认无误 → 用文字层原文；否则取三份转写的中位版本（与其余两份编辑距离之和最小） |
| 公式 / 表格 | 三份 LaTeX / HTML 取中位版本 |
| 阅读顺序 | 各人排序的平均名次 |
| 漏框文字 | 至少 2 人报告同一段文字 → 补进真值，框借用相邻区域并标 `attribute.box_approx`（端到端指标按文字匹配，不看框） |
| 无字文本块 | 不含任何字母数字（答题横线、引导点）→ 改为 `abandon`，不计分 |

### 为什么这样设计（给负责人看）

- **框不让大模型画**：大模型给的坐标不准。几何精度由检测器与文字层保证，大模型只做“改类别 / 删框 / 排序 / 转写”。
- **文本以文字层为准**：原生 PDF 的文字层就是排版用的原文；但老式非 Unicode 字体（天城、阿拉伯）会让文字层变乱码，
  所以要 2 人确认才用，否则用转写。
- **自评偏差**：被测的 7 个模型里有 GPT-6-Astra 和 Opus 5.5。对策是 Gemini 作为不被测的标注者参与并负责打破平局；
  原始答案全部保留，评某个模型时可以去掉它的那一票重建真值（留一法），门户报告两种真值下的分数差。
- **一致率要打折看**：区域和顺序都是检测器先提出的，标注者倾向于接受，所以一致率会被“锚定”抬高；
  它能说明三人没有大的分歧，不能证明真值一定对。

## 3. 文件与格式

发布包由 `python3 -m synthdog_doc.evalset.release --out <dir>` 生成：

| 文件 | 内容 |
|---|---|
| `omnidocbench_gt.json` | 真值，每页一条，OmniDocBench 格式；`page_attribute` 另有 `sdd_lang`、`sdd_doc_type`、`born_digital` |
| `manifest.jsonl` | 每页的原始网址、域名、PDF SHA-256、页码、渲染 DPI、图像尺寸、许可层、CommonCrawl dump / WARC 文件 / 偏移 |
| `images/` | A 层页面图像 |
| `render_pages.py` | 从原始 PDF（原网址或 CommonCrawl WARC）重建任意页面图像，校验 SHA-256；抽测与发布图像逐像素一致 |
| `agreement.jsonl`、`annotations/` | 每页一致性统计、三位标注者的原始答案（用于留一法） |
| `README.md` | 英文数据卡 |

### 许可分层

- **A 层**：政府、教育、政府间组织域名（`.gov`、`.edu`、`.ac.xx`、`.int`、`europa.eu` 等）的文档，发布页面图像 + 标注。
- **B 层**：其余文档只发布指针（网址、WARC 位置、页码、哈希）+ 渲染脚本 + 标注，限研究用途，提供下架通道。
- 分层按域名粗分，**对外发布前仍需逐份核对 A 层文档的许可**。标注本身按 CC BY 4.0。

## 4. 评测怎么跑

真值是标准 OmniDocBench JSON，直接用 step-dataloop 的评分工具：

```bash
cd /data/code/step-dataloop/serve-evaluate
GROUP=hw910_edge bash scripts/odb_eval.sh --job <模型名>:<发布包>/omnidocbench_gt.json:<预测目录> --out <输出目录>
```

预测目录里每页一个 `<page_id>.md`。分语言 / 分版面结果在 `summary.json` 的 `by_page_attribute`（`sdd_lang`、`sdd_doc_type`）。

## 5. 已知局限

- 没有人工核验；标注质量以三方一致率、文字层比例和留一法偏差作旁证。
- 中小语种的报纸、杂志、PPT 凑不齐 5 份，覆盖矩阵如实留空。
- 漏框文字的框是近似的（已标记）；端到端指标不受影响，版面检测类指标请排除这些块。
- 许可分层是域名启发式，A 层发布前需逐份确认。
